# 0xlabel: a simple wallet labeler

The implementation is in the repository root. [Start the helper and install the extension](../INSTALL.md), or read the [test coverage](testing.md). The explanation below is the architecture, written to read comfortably aloud.

The product should feel like the websites you already use have learned the names you give to addresses. Name a wallet once, recognize it wherever it appears, and keep using the page naturally.

The baseline is one small Python process per API installation, one SQLite file for that installation, and one Chrome extension. The service runs on your laptop by default, and the same service can run remotely. Local and remote installations own independent books. FastAPI, Uvicorn, and Python's built-in SQLite support are sufficient. Use direct SQL and one table.

The extension uses ordinary JavaScript and CSS. One background worker owns authenticated API calls and persistent caches separated by API address. One shared content script owns scanning, annotations, and the inline editor. A small popup contains settings, search, and status. Chrome runs the worker; there is no extra synchronization process to start.

The popup and editor use a heavy minimalist aesthetic: bold typography, quiet black-and-white surfaces, soft corners, and restrained royal-blue accents. Controls are borderless, with subtle edges and spacing providing structure. The [style guide](style.md) makes that direction explicit. Native website highlights retain their own appearance.

One command starts the helper and initializes its database and random access token. Paste the connection details into the extension once. Local connections use the laptop's loopback interface; remote hosting uses HTTPS. The operating system can start that same command at login. A custom installer or background-service manager is outside the baseline.

The popup can save a Local connection and a Remote connection, each with an API address and its own token. Grant access to that API's origin when adding it, and test a new remote connection with a read-only book download before activation. Switching between saved connections selects one book; it does not migrate or combine books. Editing an API address creates a new saved connection and leaves the previous connection intact. Rotating a token for the same installation can keep its existing cache. Remote connections go directly from the extension to the API, so the localhost helper can be stopped while its database remains safely on disk.

Use the normalized full API base URL, including its port and path, as the storage namespace. Keep each connection's settings, cached book, and last successful sync separately in Chrome's local extension storage, with one selected-connection key. There is no additional account, profile framework, or server-side identity table. If two different URLs happen to reach the same database, the extension still treats their caches separately; switching itself remains a read-only action.

Enable labeling for each site once. The popup's **Show my labels on this site** switch changes between **Your labels** and **Website defaults**. Turning it off immediately clears our labels, controls, and editor from every open tab on that site and stops future injections there. Turning it on reapplies the selected book. The choice persists; the book, API connection, and synchronization are independent of this display switch. A small, quiet label control sits inline beside each verified address or name, like a native copy control. Shortened fragments need a reliable full value from a link or attribute. Never infer identity from an abbreviation alone. Native website highlights and focus indicators keep their own styling.

The toolbar's small address book contains a blue 0x. It turns green with a faint halo when labeling is active on the current page. Its tooltip confirms that status. An inactive or loading page keeps the neutral outline, and a paused integration shows the amber warning. Existing page status drives the icon; no separate polling process is needed.

On Etherscan, a full-address link or explicit full-address attribute identifies ENS names and preset labels, including named homepage fee recipients and plain spans in transaction tables. Your saved label takes visual precedence over the site's name or address. Unlabeled addresses retain the website's display. No name lookup or extra network request is needed.

Each address has an ordered list of names. The first name in the applicable list is always displayed. A labeled row shows Treasury, with its tag icon and the site's native controls beside it. The editor shows the full checksummed address. Other names remain in the editor and search.

A [CSS-generated label](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/::before) shows the name while collapsing the original text's visible glyphs. Capture the site's font size in one namespaced CSS variable before substitution. The underlying text and children stay intact, and removing the label marker restores the native presentation. Skip address containers that include native interactive controls. Truncate long names before they push controls aside, and preserve visible keyboard focus.

Preserving native text helps copy controls continue reading addresses and respects the structure that [React manages](https://react.dev/learn/manipulating-the-dom-with-refs). Native links and copy buttons keep their jobs. Real-site layout, copying, navigation, and accessibility still require verification; generated content alone is not a reliable accessible label.

The label control is always available beside its address. Browser layout positions it, and CSS handles its hover and focus appearance immediately. There is no floating placement search, hover delay, or highlight timer. A keyboard-accessible context-menu action opens the same editor. Additional shortcut modes are unnecessary.

The label control opens one compact popover beside the address. Its header clearly says 0xlabel and uses the same royal-blue accent. Show the full address, a copy action, and the ranked names. Fit the panel inside the viewport when opening, growing, or resizing, and match the page's light or dark appearance. Position it in the document so the browser scrolls it naturally with the address, without per-scroll measurements or flipping sides. All label controls open one shared editor per page. Clicking another address replaces an untouched editor. Changed drafts and pending saves stay protected with an explanation; save or close the draft before switching. Clicking the current address's tag brings its editor back into view and focus.

The panel uses a translucent surface, a quiet backdrop blur, and a soft shadow. Its compact header includes the captured destination. The full address has a small copy icon, each label occupies one line, and a small + control and Save sit at opposite ends of the footer. The + has an Add label tooltip and accessible name. There is no network checkbox in the editor. Clicking outside or pressing Escape dismisses it without saving the draft. Outside clicks retain the website's normal focus and action. The popup's book editor also has a close control. Label fields are excluded from Bitwarden's autofill detection without changing global password-manager settings. They remain ordinary accessible textboxes, with Enter to save.

On a website, a small eye replaces the close control when a saved label exists. Show website original temporarily reveals the site's current text for every occurrence of that address on the same chain. The crossed eye restores your label with Show my label. The editor stays open, and its draft stays untouched. Scrolling, website updates, synchronization, and saving keep that comparison in place. Refreshing, navigating to another page, or switching books restores our labels. Other tabs stay independent. This is temporary page state, held in one in-memory set; it never changes the book. A detached or paused editor cannot toggle another row, and a draft from another book cannot change the current display.

Use EIP-55 checksummed addresses throughout 0xlabel's display and copy actions, including shortened book entries and manual-entry previews. Compute them locally with one small, bundled Keccak primitive. Storage, API keys, matching, and JSON exports remain lowercase. Native website text and copy controls retain their own behavior.

An unlabeled address starts with a focused empty field. An existing address selects its default name for quick editing. Add label appends a row. Move-up and move-down controls reorder names; when there are several names, the first row has a Default badge. Names can be renamed or removed in place. This single ordering rule needs no dragging, scores, or separate Make default control.

Enter in a name field saves the list. Ranking buttons retain normal keyboard behavior. Escape cancels. The editor previews the draft, but page labels change only after a confirmed write. On confirmation, Save becomes a checkmark and gives a restrained 300-millisecond blue pulse before closing. The button keeps its size and stays locked through confirmation. Reduced motion shows a still checkmark for the same brief interval. Failed saves keep the draft open and never show a success response. Capture the full address, scope, and connection when opening the editor. A recycled row cannot redirect an edit to another wallet, and switching connections cannot redirect it to another server. The editor identifies which connection will receive the save. If the selected connection changes, preserve the draft but require switching back or cancelling before saving it.

New inline labels apply globally. Editing an existing network override preserves its scope automatically. The popup's optional chain ID creates a scoped list explicitly, starting from a copy of the global names if present; book entries open their own stored scope. Select the network list when one exists, otherwise the global list, and display its first name. An unknown network uses only the global list. Each editor has one captured scope and one draft. Removing the last name removes that scoped record, revealing the global list or original page display. Explain that outcome before saving.

SQLite stores one row per address and scope: an ordered JSON array of names and one edit-conflict token. Array order is priority. Normalize addresses, trim names, reject duplicates within a list, and set a modest length limit. Comparing the token prevents older edits from silently overwriting newer changes. A conflict preserves the draft and shows the current list.

The API has two operations: download the book, and replace one scoped address list. Saving an empty list removes the scoped record. Writes use short transactions and return the confirmed record and its edit-conflict token, or confirmation of removal. Every request requires the access token. There are no separate alias, ordering, history, or bulk-import endpoints.

Keep a persistent cached book for each saved API address, with only one connection active. Supported pages receive that selected book and perform local lookups. Five hundred addresses require no API calls to display cached labels. After a save, the worker updates the correct cache and open pages using that connection. Adapters have no knowledge of servers or synchronization.

Periodic synchronization is a read-only pull. One [Chrome alarm](https://developer.chrome.com/docs/extensions/reference/api/alarms) runs about once a minute while Chrome is running and downloads the selected API's complete book. Also refresh on activation, startup or wake, browsing resume, and manual Refresh. Coalesce these triggers so at most one download is in flight, and serialize downloads with saves. Chrome may delay alarms or coalesce missed ticks after sleep; there is no catch-up queue. Ensure the alarm exists whenever the worker starts.

After a successful response, validate the entire snapshot and replace only that connection's cached book in one storage write. Full replacement correctly reflects deletions and rankings without a diff protocol. A failed request, invalid response, or timeout preserves the previous snapshot and last successful sync time. Show a quiet cached-data status and try again on the next scheduled tick or explicit refresh. Background sync never uploads cached labels, merges databases, or falls back to another connection.

Every request captures its API address and token before starting, uses a short timeout, and treats redirects as errors. A response cannot be filed under whatever connection happens to be selected later. Ignore download results if the selection or credentials changed during the request, including a switch away and back. Outgoing writes stay bound to the original connection; the worker rejects an edit whose connection is no longer selected. These small guards prevent late requests or stale editors from mixing books.

For example, after building a book on localhost, adding a remote API changes only the selected connection and its own cache. The localhost SQLite file and cached Local book remain intact. An empty remote book means an empty Remote cache, never an instruction to clear Local data. Open pages use the Remote book exclusively, clearing old Local annotations before applying it. Switching back immediately uses the retained Local cache and refreshes from localhost. Both switching and automatic sync contain only reads of the APIs; an explicit Save is the only operation that changes an API's database. Moving labels between installations would require an explicit future transfer feature.

Chrome can [stop an idle worker](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle), so saved connections and their books live in persistent storage. A stopped helper or sleeping laptop does not erase cached labels. Use the selected connection's cached book when it is unavailable; never substitute another server's book. Saving requires a connection, and an uncertain save triggers a refresh of the original connection before retrying. There is no offline write queue, rapid retry loop, or background sync service.

The popup contains a simple connection selector, connection settings, last sync time, site status, search, manual full-address entry, and a JSON export of the selected book. Search opens the same editor or copies the full address. Export uses that connection's book as a portable backup and excludes credentials. Import previews, automatic migration, Undo, scheduled rotating backups, and a separate management application are outside the baseline.

Search runs directly against the selected cached book. Prepare its searchable text once per snapshot, build each visible row and checksum once, and reuse rows as the query changes. Leave unchanged results and messages alone. Typing needs no API request or delayed search timer. The inline editor also updates its draft directly, with positioning reserved for changes that affect the panel's size or location.

Etherscan and Safe are the first integrations. An adapter is one small read-only module with three plain functions: match the site, probe its structure, and scan a supplied branch for address targets. Each target identifies a full address, an existing display element, and an optional network. The shared core owns every mutation, editor, observer, API call, and cleanup.

These functions stay in a static registry. Two helpers handle inclusive element queries and canonical address parsing. New adapters start by copying an example, registering it, and adding HTML fixtures. A companion adapter reference defines the contract. Ordinary fixture tests reuse the real core with fake labels. A plugin framework, dedicated preview application, and debug dashboard are unnecessary. Adapters ship with the extension; the server supplies data only.

One mutation observer processes changed branches in small batches, ignores the extension's own markers, and revalidates reused elements. Clear old annotations as soon as an address changes or becomes unresolved. Names use styling, and label controls use ordinary inline layout; measure geometry only for an open editor. A conservative generic adapter handles full addresses on other enabled sites.

Ordinary hover styling keeps verified addresses available. Adding or removing a page-root tooltip scans its own branch rather than every address. Inline label controls require no positioning reads or hit tests on hover, mouse movement, or resize. Their small shadow roots reuse one stylesheet; inserting or removing owned UI does not trigger another address scan.

Loading, an empty supported page, and an unsupported route are ordinary states. Confirmed structural failure, contradictory address evidence, or an exception pauses the adapter. Remove its names and label controls, preserving native browsing. Do not mask failure by switching a stale site adapter to the generic detector.

One amber indicator leads to a short popup message naming the integration, with Retry and Turn off for this site. Technical reasons stay in local diagnostics. A passing fresh probe resumes labeling. Failure never deletes the book. A stopped Python helper is a distinct connection state; a healthy adapter can keep showing cached labels.

If an editor is open during adapter failure, preserve its address, scope, and draft. Detach it from the failed target and show a short notice. Saving can still update the book while the paused page receives no annotations. Cleanup removes only extension-owned markers and UI. Native text, links, inputs, transaction data, signing controls, and subsequent page changes remain intact. Read-only transaction-summary addresses are eligible for annotation.

Websites can read displayed names and their attributes. That privacy tradeoff is intentional. Saving uses our API exclusively, and credentials stay in trusted extension storage using [Chrome's access restrictions](https://developer.chrome.com/docs/extensions/reference/api/storage). Content scripts receive labels, never the token, and cannot direct the worker to arbitrary servers.

Implementation should prove address detection, label control reachability, ranked editing, persistence, native copying and navigation, keyboard access, and cleanup on Etherscan and Safe. Check five hundred addresses, changing rows, stale adapters, failures during editing, disconnected helpers, scoped lists, and conflicting saves. Also verify that periodic pulls reflect remote changes and deletions, failed pulls preserve snapshots, an empty Remote book cannot clear Local data, and late responses and open drafts cannot cross connections. Switching Local to Remote and back must preserve both caches and perform no database writes. These are reliability checks, not new runtime components.

The implementation tests the shared renderer across five hundred addresses, including native text, links, selection, and copy behavior. Backend, cache, editor, and recovery checks accompany it. The same page controller has also been checked on live Etherscan and Safe; the verification notes describe the limits of those checks.

Keep the implementation at this size: one Python process and SQLite file per API installation, one extension worker with one periodic alarm, a small collection of caches keyed by API address, one shared page controller and editor, a small popup, and plain adapter modules. Add abstractions only when a demonstrated implementation need justifies them.

This is a greenfield development app. The helper and extension use one current contract. Change them together, remove obsolete formats, and make hard cutovers without migration or backward-compatibility layers. The [development policy](../AGENTS.md) records that rule. Edit-conflict tokens and message-order counters serve data integrity, independently of release versions.
