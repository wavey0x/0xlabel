# 0xlabel style

The visual direction is **heavy minimalism**: a small, deliberate interface with bold typography, generous clarity, and very little decoration. Weight and spacing create structure; controls should feel quiet and easy in both light and dark mode.

Use near-black and white flat surfaces, with neutral gray for secondary information. Royal blue, `#4169e1`, identifies the brand, primary action, labels, and keyboard focus. Amber is reserved for warnings.

The toolbar icon is a simple outlined address book with a blue 0x inside. Its outline is neutral gray by default. When the current page's adapter is ready, the outline turns green with a very faint green halo. Loading, unsupported, and disabled pages keep the neutral icon; a paused adapter also shows the amber warning badge. Use static icons and an accessible status tooltip, with no pulse or animation. Keep the editable source in `extension/icons/book.svg`; regenerate the supplied PNG sizes with `npm run icons` after changing it.

Headings use heavy system type, roughly 800–850 weight. Actions and field labels use 700–750. Body text stays readable; wallet addresses use compact monospace. Emphasize hierarchy through weight and spacing.

Use borderless inputs and buttons on soft neutral surfaces, with six-to-eight-pixel corners. The editor has twelve-pixel corners, a faint one-pixel edge, and a broad, soft shadow that separates it from the website. Its glass surface is eighty percent opaque in dark mode and eighty-six percent in light mode, with a sixteen-pixel backdrop blur to keep underlying content from competing with the text. Apply this effect only to the open editor; the label control stays plain and quick. Supporting rules are subtle. The inline label control is a royal-blue fourteen-pixel glyph in a twenty-pixel control with four-pixel corners and a transparent background. Hover and keyboard focus add a restrained blue glow immediately, without changing size or position. Keep idle controls still; reserve motion for a brief confirmed-save response.

Keep spacing compact and consistent. Use comfortable hit targets, clear focus rings, and restrained hover fills. Let content determine the height; avoid extra ornament or empty panels.

The editor is 320 pixels wide with twelve-pixel padding. Put the small brand, captured destination, and header action in one line; the full checksummed address and copy icon in the next line; and each label and its controls in one compact row. On a website, use a fourteen-pixel outlined eye in a twenty-four-pixel control instead of a close icon. The open eye offers Show website original; the crossed eye offers Show my label. Keep it neutral at rest, blue on hover, and omit it without a saved override. The popup's book editor keeps its close control. A twenty-eight-pixel + control sits at the left of the footer and a fixed-width Save button at the right, without a network checkbox, separator, or extra Cancel button. Give the + an Add label tooltip and accessible name. Clicking outside or pressing Escape cancels without saving. Outside clicks keep their normal website action; tag controls retain the existing draft-switching behavior. Use an overlapping-squares copy icon and a checkmark confirmation in both the editor and book. A successful save shows that checkmark with a gentle blue pulse for 300 milliseconds, then closes; reduced motion keeps the checkmark still. Animate only the button so the panel stays anchored. Align controls along the right edge. Show Default only when several labels need an ordering distinction, and hide removal controls on the single empty field. The captured destination stays visible; warnings and deletion previews take space only when relevant.

Use one soft focus ring around the label row, rather than a separate heavy frame around its input. Call the field a Label, not a personal Name. Display and copy full addresses in EIP-55 checksum form; keep lowercase only in storage, matching, API records, and machine-readable exports. Shortened addresses shown by 0xlabel retain the case of their full checksum form.

On a website, use a simple outlined tag as the label icon. It sits inline immediately after its address or canonical link, before the native copy control where present. Keep it available at rest, matching the quiet native icons. Let browser layout position it. Never use floating coordinates, delayed visibility, or extra dashed address highlights. Native typography, highlights, controls, and focus indicators retain their own styling. Strong type belongs to 0xlabel's popup and shared editor. The open editor scrolls naturally with its address; scrolling alone must not flip or clamp its placement. Hide ranking arrows when there is only one name, and show Default once when there are several.

Show one visible identity per labeled address: the user's default label supersedes the site's name or address. Give the text a little inline padding so italic glyphs are not cut off by truncation. Keep the tag and native copy control close to that label. In the popup, use one quiet per-site switch beside the hostname, with Your labels or Website defaults underneath. The on state uses royal blue; the off state uses neutral gray. Switching is immediate, with no appearance animation or extra global display setting.

The implementation lives in `extension/popup.css`, `extension/editor.css`, and `extension/page.css`. Apply this direction consistently when extending them.
